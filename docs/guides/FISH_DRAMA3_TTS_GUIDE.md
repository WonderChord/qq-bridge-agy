# AI 角色高表现力语音（TTS）实战指南：基于 Fish Audio Drama 3 与 48kHz 频域嫁接

这份指南总结了一套经过实测验证的 **AI 角色高表现力语音（TTS）工程方案**。针对传统 TTS 常见的**「人机播音腔」「高频发闷」「耳语失控」「长句尾音飘逸」**四大痛点，从**参考音选材、48kHz 高频重建、Drama 3 三层导演编排语法、动态情绪底包路由、短句自动分句**五个环节给出可直接复用的完整做法。

---

## 一、为什么很多 AI 语音听起来「像人机 / 没灵魂」？

在 Zero-Shot（零样本瞬时克隆）语音大模型中，模型不仅克隆参考音频的**声带音色（Timbre）**，还会 1:1 复刻参考音频里的**说话姿态（Prosody & Attitude）**。常见翻车原因主要有三个：

1. **选错语体（敬语 vs 口语）**：
   如果参考音频里全是礼貌敬语（如日文 `〜です / 〜ます`）或一板一眼的系统播报腔，哪怕台词写成亲昵口语，合成出来的声音依然像「客服机器人在念稿」。
2. **高频截断与底噪污染**：
   绝大多数游戏解包语音或网络音频是有损压缩（MP3/OGG），在 `15kHz~16kHz` 处存在砖墙式高频截断。直接喂给高采样率模型，会导致唇齿气音、贴耳呼吸感丢失；而单纯用超分模型全频段重绘，又会破坏中低频原本的声带质感。
3. **单次生成文本过长**：
   自回归声学模型在单次生成超过 `45~50` 个字符、跨越三四个转折句时，句末声学 Token 容易出现轻微发散（「小飘逸」），且首包等待时间过长。

## 二、参考音频选材与「多情绪分包」黄金法则

### 1. 选材四条铁律
1. **100% 纯口语（タメ口）**：做日常陪伴、恋爱或灵动人设，参考音频必须全部挑**熟人/恋人间的松弛口语**，彻底剔除敬语朗读句。
2. **近讲效应（Close-to-Mic）与微表情气音**：优先挑带有**轻笑（如 `くふふっ`、`ふふっ`）、尾音上扬钩子（`〜よっか？`）、鼻音哼唧（`ふぅん…`、`へぇ、ふ～ん？`）和贴耳吐息**的干声片段。
3. **剔除原角色自称与出戏设定词**：如果原音频里包含原角色第三人称自称或特定世界观名词，直接弃用或用音频剪辑切掉，只保留纯第一人称（`私 / あたし`）的自然句子，防止模型在自由生成时产生风格粘连。
4. **严格一字不差的 `reference_text`**：Zero-Shot 挂载参考音频时，配对的日文/中文转写文本（含标点、拖音符 `〜`、笑声词）必须与音频内容 100% 对齐，避免音素对齐偏移导致吞字。

### 2. 不要只用 1 条参考音：构建 5~6 组「情绪参考底包」
单条参考音频无法覆盖所有情绪。最佳实践是挑选同一声优的 15~20 条短干声，按情绪分类拼接成 **5~6 组、每组 15~25 秒的参考底包**（段与段之间插入 `350ms` 纯净零电平静音作为自然气口）：

| 底包编号 | 适用场景 | 包含的声学特征 |
|---|---|---|
| `01_default_lively` | **默认主参考（贴耳微醺 + 欲擒故纵）** | 近麦呼吸感、从容低笑、尾音上扬反问 |
| `02_teasing_cute` | **狡黠看穿 / 拖长音逗弄** | 高低起伏的 `へぇ、ふ～ん？` 连环调侃、灵巧语速 |
| `03_sweet_whisper` | **私密贴耳 / 温柔耳语** | 成熟微醺气声、放软的句尾、贴耳甜笑 |
| `04_shy_clingy` | **心动撒娇 / 粘人求抱** | 语速微快的心跳感、软糯鼻音哼唧 |
| `05_special_reward` | **偏心奖励 / 一字一顿勾引** | 慢速拉长重音（如 `あ・げ・る♪`）、愉悦尾音 |
| `06_smug_flustered` | **促狭坏笑 / 玩过头装无辜** | 得意偷笑转突然收声的心虚感 |

## 三、48kHz AudioSR 高频重建 + STFT 低频零损嫁接管线

为了兼顾**「原声优 100% 纯正的中低频声带质感」**与**「录音室级 48kHz 的唇齿空气感」**，采用 **频域分带嫁接（Frequency-Band Grafting）** 方案：

- `< 12.5 kHz`：**100% 保持原始干声的 STFT 复数频谱（幅度 + 相位零损失）**，确保声优原本的音色、胸腔共鸣毫无涂抹感；
- `12.5 kHz ~ 14.5 kHz`：**余弦汉宁窗（Hann Window）平滑交叉淡入淡出**，彻底消除频段拼接台阶；
- `> 14.5 kHz`：**注入 AudioSR（50 步 DDIM）重建的 14.5kHz~22kHz 高频泛音与吐息空气感**，并乘上基于原声 RMS 能量的动态噪声门限，杜绝静音气口出现扩散底噪。

### 核心嫁接实现（Python）

```python
import numpy as np
import librosa

def stft_graft_low_high(orig_48k: np.ndarray, sr_48k: np.ndarray, sr: int = 48000) -> np.ndarray:
    """
    保留 <12.5kHz 原始相位与音色 100% 零损，
    12.5kHz~14.5kHz 余弦平滑过渡，
    >14.5kHz 采用 AudioSR 重建的高频空气泛音，并对静音段施加包络门限消除底噪。
    """
    n_fft, hop = 2048, 512
    length = min(len(orig_48k), len(sr_48k))
    orig_48k, sr_48k = orig_48k[:length], sr_48k[:length]

    D_orig = librosa.stft(orig_48k, n_fft=n_fft, hop_length=hop)
    D_sr = librosa.stft(sr_48k, n_fft=n_fft, hop_length=hop)
    freqs = librosa.fft_frequencies(sr=sr, n_fft=n_fft)

    # 构造频域交叉淡入权重 w_sr (0 = 纯原声, 1 = 纯超分高频)
    f_low, f_high = 12500.0, 14500.0
    w_sr = np.zeros_like(freqs)
    trans = (freqs >= f_low) & (freqs <= f_high)
    w_sr[trans] = 0.5 * (1.0 - np.cos(np.pi * (freqs[trans] - f_low) / (f_high - f_low)))
    w_sr[freqs > f_high] = 1.0
    w_sr = w_sr[:, None]

    # 对超分高频施加原声能量包络门限，杜绝静音期产生扩散模型底噪嘶声
    rms = librosa.feature.rms(y=orig_48k, frame_length=n_fft, hop_length=hop)[0]
    gate = np.clip((rms - 0.002) / 0.008, 0.0, 1.0)[None, :D_sr.shape[1]]

    D_out = (1.0 - w_sr) * D_orig + (w_sr * gate) * D_sr
    y_out = librosa.istft(D_out, hop_length=hop, length=length)

    # 峰值归一化至 -1.0 dBFS (0.891)
    peak = np.max(np.abs(y_out))
    if peak > 1e-5:
        y_out = y_out * (0.891 / peak)
    return y_out.astype(np.float32)
```

## 四、Fish Audio Drama 3 三层导演编排语法（严禁混淆 `[]` 与 `<>`）

Fish Audio **Drama 3**（请求头指定 `model: drama-3`）将控制标签划分为**「方括号 `[]` 句级演技/点状事件」**与**「成对尖括号 `<tag>...</tag>` 局部词句投递」**两套正交体系：

### 1. 第一层：句首方括号自由导演指令 `[...]`（Sentence Direction）
- **位置**：放在句首或分句前。
- **跨语种讲戏特性**：**演技指令可以用任意语言编写（中文/日文/英文均可），无需与台词正文语种一致**。
- **高表现力四要素公式**：`[声线质感/吐息状态 + 角色神态动作 + 距离感 + 语气目的]`
  - 普通写法（干瘪）：`[happy] ねえ、どう？`
  - **导演讲戏写法（极佳）**：`[色っぽく艶のある甘い吐息交じりの声で、小悪魔っぽくからかうように耳元で誘惑するトーンで] [chuckling] くふふっ、ねえ、どう？`

### 2. 第二层：句中点状生理音效与停顿 `[...]`（Point-in-Time Tags）
直接嵌在呼吸、笑声或停顿发生的精确位置。**黄金技巧：音效标签后面紧跟对应语种的拟声词，衔接最自然**！

| 类别 | 标准标签 | 推荐搭配示例（标签 + 拟声词） |
|---|---|---|
| **小恶魔偷笑 / 低笑** | `[chuckling]` | `[chuckling] くふふっ、引っかかったね？` |
| **少女捂嘴轻笑** | `[giggles]` / `[small laugh]` | `[small laugh] ふふっ、冗談だよ♪` |
| **贴耳换气** | `[breath]` | `<soft>ほら……</soft> [breath] <whisper>もっと近くにおいで？</whisper>` |
| **微醺吐息 / 叹气** | `[sighs]` | `[sighs] ふぅ……やっと二人きりになれたね。` |
| **急促呼吸 / 害羞破防** | `[panting]` / `[shaky breath]` | `[panting] はぁ、はぁ……ちょっと待ってってば！` |
| **突然惊呼** | `[gasps]` | `[gasps] えっ！？今なんて言ったの！？` |
| **困倦哈欠 / 撒娇哼唧** | `[yawning]` / `[groaning]` | `[yawning] ふわぁ……なんだか眠くなっちゃった。` |
| **气口停顿** | `[short pause]` / `[long pause]` | `ふぅん…… [short pause] 気になるなら教えてあげよっか？` |

### 3. 第三层：成对尖括号局部词句变形 `<tag>...</tag>`（Word-Level Span Tags）

> **核心避坑铁律**：在 Drama 3 中，**耳语（`<whisper>`）和局部放软（`<soft>`）必须使用成对尖括号 `<tag>...</tag>` 包裹目标词句**，**绝对不能写成 `[whisper]`**！
> 成对尖括号只改变标签内部的词句发音，遇到闭合标签 `</whisper>` 后**立即恢复正常声线与音量**，彻底解决传统 TTS 一旦开启耳语就整句无法恢复的问题。

| 成对尖括号标签 | 声学效果 | 实战造句示例 |
|---|---|---|
| `<whisper>...</whisper>` | **贴耳气声耳语**（声带弱化、极近麦感） | `<whisper>ここからは、二人だけの秘密だよ♥</whisper>` |
| `<soft>...</soft>` | **轻柔放软**（保留甜美基频，降低力度） | `<soft>ねえ、もう少しだけそばにいて？</soft>` |
| `<emphasis>...</emphasis>` | **重点字词突出**（拉开音高包络） | `特別なご褒美を <emphasis>あ・げ・る♪</emphasis>` |
| `<slow>...</slow>` | **局部拖音放慢**（欲擒故纵、慢条斯理） | `へぇ、ふ～ん？ <slow>それって、どういう意味かなぁ？</slow>` |
| `<fast>...</fast>` | **局部加速连读**（被反撩破防时慌张抢白） | `えっ！？ <fast>ち、違うってば！今のなし！</fast>` |
| `<stress>...</stress>` | **字头重音咬字** | `<stress>絶対</stress> に許さないからね！` |
| `<forceful>...</forceful>` | **用力笃定发声** | `<forceful>もう知らない！</forceful>` |

## 五、工程落地：MessagePack 零样本动态挂载 + 智能短句分句

### 1. 为什么用 MessagePack 实时传参考音频，而不在网页建固定模型？
Fish Audio `/v1/tts` 接口支持 `Content-Type: application/msgpack` 直接传入二进制参考音频字节流：
- **零额外费用**：API **只按目标台词 `text` 的 UTF-8 字节数计费**，随请求上传的 `references` 音频完全不计费；
- **每句话动态切情绪底包**：可根据当前台词中的标签（例如检测到 `<whisper>` 自动切 `03_sweet_whisper.wav`，检测到 `<slow>` 或调侃词自动切 `02_teasing_cute.wav`），让同一个角色在不同句子里拥有最地道的情绪底色。

```javascript
// 请求载荷结构（使用 msgpack 编码后 POST 至 https://api.fish.audio/v1/tts）
const payload = {
  text: normalizedDrama3Text,
  format: 'mp3',
  mp3_bitrate: 192,
  normalize: true,
  temperature: 0.7,
  top_p: 0.7,
  latency: 'normal',
  references: [
    {
      audio: chosen48kWavBuffer, // 48kHz 修复 WAV Buffer
      text: chosenExactTranscript // 一字不差的原音频台词
    }
  ]
};
```

### 2. 短句分句原则（消除长语音尾音飘逸 + 提升 2 倍实时性）
- **单条语音黄金长度**：控制在 **`15~38` 个实际发音字符（1~2 个短分句，时长约 3~6 秒）**。
- **多段连发优于单条长语音**：当角色要说一段较长的话时，将其拆成 **2 条短语音依次合成发送**：
  - **第 1 条（铺垫与轻笑，6秒）**：
    `[色っぽく艶のある甘い吐息交じりの声で、小悪魔っぽくからかうように] [chuckling] くふふっ、了解だよ♪ これからは短く区切って、耳元でちょっとずつ囁いてあげるね。`
  - **第 2 条（贴耳慢放软 + 耳语绝杀，5秒）**：
    `[甘く囁くように距離を詰めて] <soft>ほら……</soft> [breath] <whisper>こういう方が、もっとゾクゾクするでしょ？♥</whisper>`
- **代码层自动分句器兜底**：在发送端脚本中检测去除标签后的实际发音字数，一旦单条超过 `42` 字，自动在不破坏 `<whisper>...</whisper>` / `<soft>...</soft>` 闭合区间的前提下，按 `[short pause]` 或句末标点（`。！？♪♥`）切分为多条短句，并自动将句首的 `[导演讲戏指令]` 继承到每一段子句开头依次发送。
