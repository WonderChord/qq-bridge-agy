# 群友人设总结要点与双层分舱记忆归档指南

本文档总结 `qq-bridge-agy` 的**群友人设提炼规范（百字常驻 + 深度详档）**与**旁路异步双层记忆归档架构**，在不破坏 Worker 线程 KV 缓存的前提下，让机器人既认识群里每一位常驻成员，又能随时调出某位群友的完整装备拓扑、人际约定与历史名场面。

---

## 一、三层群聊记忆与单向隔离架构

每个群聊舱位（如 `memory/groups/<group_dir>/`）与私聊舱位（`memory/creator_private/`）采用物理目录隔离，并在群聊内划分为三层存储：

| 层级 | 文件路径 | 容量上限 | 注入时机 | 核心职责 |
| :--- | :--- | :--- | :--- | :--- |
| **L1 日常常驻摘要** | `summary.md` | `<= 7500` 字 | Worker 建新或文件变更时注入 1 次 | 群总纲、群体黑话共识、Creator 群内画像，以及**每位常驻群友约 100 字的日常核心人设** |
| **L2 群友深度详档** | `people.md` | 每人 `200~350` 字 | 按未读发言人/昵称/关键词动态打分巡回，每轮最多挂载 4 人（12 轮冷却） | 每位常驻群友的**详细装备拓扑、专业背景、人际交集约定与历史名场面** |
| **L3 历史事件日记** | `diary/YYYY-MM-DD.md` | 按日追加 | 命中未读话题关键词（`score >= 6`）时自动抽取 Top 3 条目 | 按日期归档的高价值群内事件、面基/联机记录、群友约定与名场面 |

### 单向隐私隔离原则
- **群聊 Worker**（当 `includePrivate: true` 时）可单向只读挂载 Creator 私聊摘要（`owner.md`，截取前 `3400` 字），保证群内与 Creator 互动时默契不断档，但严禁向群友外泄私密细节。
- **私聊 Worker** 默认只读 `creator_private/owner.md`（`<= 6500` 字），仅当 Creator 来信提及群聊、特定群友昵称或历史时间词时，才由 `recallGroupMemoryForPrivateV2` 按需检索群聊记忆与历史日记。

## 二、群友人设总结的核心要点（什么该记 vs 什么必须 SKIP）

归纳群友人设与历史日记时，最忌把一次性流水账写进长期档案导致核心设定被稀释。旁路归档遵循严格的**重要性过滤法则**：

### 1. 聊完即 `SKIP`（严禁写入长期人设）
- **单人日常饮食流水账**：某人今天自己吃了什么外卖、喝了什么饮料（如一杯咖啡、一碗拉面），无多人交集或特殊梗意义。
- **随手转发的过路资讯**：随手转的外部新闻、截图吐槽、一次性水群复读。
- **临时起哄外号**：群友间一次性的玩笑起哄，未形成长期共识的称呼。

### 2. 必须完整记录的高价值人设维度
撰写或更新某位群友的百字常驻（`summary.md`）与深度详档（`people.md`）时，优先提炼以下 5 个维度：

1. **身份标签与技术/专业主线**：职业或学业方向、擅长的技术栈/创作领域、在群内的角色定位（如硬件折腾党、摄影佬、音游人、乐队贝斯手）。
2. **持久硬件与主力装备拓扑**：长期持有的核心设备与座驾（如主力显卡/CPU/NAS 拓扑、相机机身与镜头群、主力乐器/效果器、车型与改装件、客制化外设）。**合并新事件时严禁删丢原有核心装备！**
3. **鲜明审美、爱好与核心立场**：长期推的角色/IP、常玩的游戏与段位、对特定技术或数码产品的鲜明态度与口头禅。
4. **多人交集、群内约定与欠账 Flag**：
   - 谁和谁约好一起吃什么、去哪面基、联机打什么游戏；
   - 哪几个人已经一起去吃了什么、旅拍或线下聚会；
   - 群内立下的请客/欠账 Flag、借号/二手交易/技术互助记录。
5. **与机器人及 Creator 的互动默契**：平时怎么称呼机器人、常聊的话题切入点、互动时的梗与分寸。

## 三、`people.md` 标准语法格式与动态巡回机制

`src/memory-compartment.js` 中的 `parsePeopleProfiles()` 会自动解析 `people.md` 并建立内存索引（按文件 `mtimeMs` 缓存）。请严格按以下 Markdown 语法编写 `people.md`：

### 1. 常驻群友深度详档条目格式

每条深度详档占一行，以 `- \`主昵称\`（QQ号 | 常用名:别名1,别名2 | 关键词:触发词1,触发词2）：` 开头：

```markdown
# 群友深度详档（people.md）

- `阿泽`（10001001 | 常用名:泽哥,az | 关键词:摄影,索尼,a7cr,镜头,修图,面基）：常驻视觉与摄影主力。主力机身为 Sony A7CR 搭配 35GM 与 70-200G2，习惯在周末约群友出门扫街与漫展返图；桌面主力机为 9950X + RTX 5080 双屏修图工作站。性格随和但对色彩管理极度较真，曾立下「下次线下聚会包揽全员胶片合影」的 Flag，与群内硬件党常讨论 NAS 照片冷备方案。
- `小林`（10001002 | 常用名:林林,kobayashi | 关键词:贝斯,乐队,效果器,音游,maimai,联机）：群内乐队贝斯手兼街机音游常客。主力琴为日芬 Jazz Bass，常在群里分享排练室录音与效果器链折腾心得；工作日晚间常出没机厅打 maimai，周末固定与群友联机打合作生存游戏。说话风趣爱接梗，曾把备用声卡借给群友救急。
```

### 2. 其他活跃群友速查行（可选）

对于暂未积累满 200 字但需要机器人在群内认出身份的群友，可在文件末尾用一行 `其他活跃群友速查` 汇总（用 `；` 分隔）：

```markdown
- **其他活跃群友速查**：`小周`（10001003）：嵌入式开发，常聊树莓派与开源掌机；`阿K`（10001004）：模型涂装党，擅长高达喷涂与桌面布景。
```

### 3. 动态打分与 12 轮 KV 缓存保护规则

每次群聊唤醒（`recallGroupMembersForGroupWakeV2`）时，桥接层会结合**本轮未读消息 + 最近 4~8 条群消息**对 `people.md` 中的条目打分：
- **未读消息直接发言人**（UID 命中）：`+12` 分
- **最近 8 条消息发言人**（UID 命中）：`+5` 分
- **消息正文提及群友主昵称或常用名**：`+9` 分
- **消息正文命中该群友的 `关键词`**：每个命中词 `+4` 分

**防重复注入（保护 Prompt Cache）**：
- 每轮按得分从高到低最多选出 **4 名**群友的深度详档挂载到本轮增量前缀中。
- 某位群友的深度详档一旦在当前 Worker 线程挂载过，其档案已留在上下文历史中；除非间隔达到 **12 轮以上**且该群友再次直接发言，否则不会重复下发。
- 若本轮为刚换新线程或主动冒泡、尚无高分命中，系统会按游标自动巡回补充 **2 名**尚未挂载过的常驻群友详档。

## 四、旁路异步归档工作流（零阻塞）

1. **触发条件**：当某群聊或私聊自上次归档以来新增消息达到阈值（默认 `archiveEveryMessages: 60`）且距离上次归档超过冷却时间（默认 `archiveMinIntervalMs: 3600000`），`maybeEnqueueMemoryArchiveV2` 自动将批次推入后台队列。
2. **消费归档**：后台 `qq-memory-archivist` 子代理通过 `node scripts/agy-wait-archive.mjs` 阻塞式长轮询领取任务，按重要性过滤法则同步更新 `summary.md`、`people.md` 与 `diary/YYYY-MM-DD.md`，随后回传 `--done-id` 完成闭环，全程对主聊天线程零阻塞。
